# Panel spec (interactive website, no video)

The reader is an ML researcher (JEPA world models, continual learning, memory) who wants deep intuition for this paper. Each panel teaches ONE idea thoroughly: a live, genuinely interactive figure on the left, and a substantial prose column on the right (typically 350–700 words across `text`, `steps`, `after`) with equations (KaTeX: `$…$` inline, `$$…$$` display; escape backslashes inside JS template strings: `\\alpha`). Prefer more explanation over less, but every sentence must earn its place: plain, precise, no filler, no em-dashes, no emoji.

## Style (match the user's own site; see `assets/css/base.css`)
White page, black hairlines, ONE blue accent (`var(--blue)` #2f3cff, tints `--blue2/3/4`), mono labels (JetBrains Mono), serif prose (Source Serif 4). Figures are thin-line schematics and plots: `lib.frame(parent, {label:'ENCODER', sub:'f<sub>θ</sub> · ViT'})` gives the framed box with corner "+" marks, an uppercase mono label and a mono subtitle; dashed frames (`dashed:true`) for sub-modules. Canvas drawing via `lib.*` (engine helpers in light theme: `lib.C` palette: ink #111, muted, faint, rule, blue, blue2, blue3, blue4, bad #d4421c; energy colormap `lib.cmap` = deep blue (low) → white (high)). Use `lib.quantile(grid, q)` for heatmap ranges so basins are visible. Baseline models are drawn in ink/gray (solid or dashed), EBT in blue. Ground truth / targets: crosshair or dashed circle (shape, not color). Controls are bracketed mono buttons (`lib.button`), segmented mono toggles (`lib.segmented`), thin sliders (`lib.slider`). Use numbered steps (`steps: [...]`) to walk through a mechanism; `figure().step(i)` must visibly change the figure for every step.

## Mechanics
- One file per panel: `assets/js/panels/<id>.js` calling `EBT.panel({...})` (see the header comment of `assets/js/lib.js` and the reference panel `assets/js/panels/descent.js`). Optional CSS: `assets/css/panels/<id>.css` with selectors scoped to `#<id>`.
- Offline from `file://`: no fetch, modules, CDNs. Data via `lib.data('toy2d')` etc. (`window.EBT_DATA`, built by `python3 src/bundle_data.py` from `data/*.json`), images via relative paths (`media/...`). `EBT.toy2d` (assets/js/toy2d_model.js) runs the toy 2-D EBT live (energy, energyGrad, descend, grid top-down, storedGrid top-down, toPx/fromPx).
- Animate only while visible: implement `show()`/`hide()` in the object returned by `figure()` and stop timers/rAF in `hide()`. Respect `lib.reducedMotion`.
- Every figure gets provenance tags through `source: [{kind:'paper'|'toy'|'ext'|'concept', note}]` and inline mentions where mixed. Paper numbers must match `notes/paper_facts.md` (verified single source of truth; it also lists subtle traps). Toy results are toy results. Planning/MPC/JEPA are beyond the paper.
- Responsive: at 390 px the figure stacks above the text; no horizontal page scroll; canvases scale by width (`lib.canvas` does this); text ≥ 14 px.
- Test: `cd /home/user/Random/ebt-explainer && python3 src/bundle_data.py && node src/shot_panel.js <id> [step]` writes `video/frames/panel_<id>[_sN]_{desktop,phone}.png` and prints errors and overflow (ignore the "missing files" count: other panels are being built). LOOK at the PNGs for every step. Use `ACTIONS="..."` to click/drag before the shot. Performance: no per-frame work above ~8 ms; precompute grids.
- Reusable legacy code (dark-theme labs written earlier, solid logic, restyle when porting): `legacy/sections/{families,landscape,training,thinking,data,scaling,planning,takeaways}.js`.

## Panels (24). Each: what it must explain, equations, figure, steps, data, traps.

### Part I · The question
1. `system2` — "Thinking fast, thinking slow, and the question this paper asks". System 1 vs System 2 (paper's lunch vs career example, p.1–3). Why per-prediction compute matters. Today's System 2 recipes (RL with verifiable rewards: only math/code; external verifiers/reward models: extra supervision; mostly text) and their limits; the core question (p.2) verbatim; the answer in one sentence; the 3 headline results with honest context (35% = best axis; 29% relative to EBT's own no-thinking baseline; 99% fewer = 3 vs 300 passes). Figure: an interactive "difficulty dial": tasks of rising difficulty; a fixed-compute model spends the same bar each time, a thinking model spends more where needed; show both accuracy-style outcome curves conceptually (concept tag). Steps: System 1 → System 2 → current recipes → the question → the answer.
2. `families` — "Four ways to predict the next token". AR Transformer, RNN, Diffusion Transformer, EBT (paper Fig 1, Table 1, Sec 6.1–6.4). Interactive: pick easy/hard prompt and a forward-pass budget; each lane animates its real mechanism and counts passes; EBT lane runs real gradient descent on a small energy (e.g. EBT.toy2d or an analytic energy over a 3-token simplex) and shows energy converging slower for the harder prompt. Explain why AR/RNN cannot spend more compute per token, why diffusion can iterate but follows a fixed schedule and predicts noise (an amortized gradient of an energy, so no score to verify with), and what EBT adds. Then Table 1 (three facets) as an interactive table (hover = reason + page). Equations: AR $p_\theta(x_{t+1}\mid x_{\le t})=\mathrm{softmax}(f_\theta(x_{\le t}))$; diffusion score $\epsilon_\theta(x_t,t)\approx -\sigma_t\nabla\log p$; EBT Eq. 1.

### Part II · Energy
3. `energy` — "What an energy function is". $E_\theta(x,\hat y)\in\mathbb R$, low = compatible; Boltzmann $p_\theta(\hat y\mid x)=e^{-E_\theta(x,\hat y)}/Z_\theta(x)$, the intractable partition function $Z$, why EBMs work unnormalized (relative likelihoods; thin data manifolds), Sec 3.1. Verification easier than generation (Sec 2.1, maze example): interactive maze where generating a path takes search (count nodes expanded) but checking a given path takes one pass. Figure: 1-D energy curve ↔ normalized probability with a temperature slider, shaded Z; maze sub-figure. Steps: energy → probability → partition function → unnormalized → verification asymmetry.
4. `landscape` — "The energy landscape". Toy EBT landscape for a chosen context: heatmap+contours (click to drop ŷ0 and watch descent) and a drag-to-rotate 3D surface (`lib.surface` returns a projector for overlaying the path). Explain what each axis is (ŷ is the prediction; here 2-D; for text it is a distribution over ~50k tokens; for images ~50k pixels), what height is, why convexity around the truth matters, the paper's Fig 3 picture (cite). Show how the landscape changes with context x (slider over x in [0,1) using live EBT.toy2d.grid, cached).
5. `two-landscapes` — "The loss landscape is not the energy landscape". The user explicitly asked "what the loss landscape is". Training loss $\mathcal L(\theta)=\mathbb E\,J(\hat y_N(\theta),y)$ as a surface over weights (toy2d.param_landscape, 2 random filter-normalized directions, Li et al. 2018) vs energy over predictions. Two gradient descents: $\theta\leftarrow\theta-\eta\nabla_\theta\mathcal L$ (learning, reshapes the energy landscape) vs $\hat y\leftarrow\hat y-\alpha\nabla_{\hat y}E$ (thinking, moves on it). Interactive: side-by-side surfaces; moving a point on the loss landscape (perturbing θ along the two directions) live-updates the energy landscape shown next to it (recompute E with perturbed weights if feasible: the param directions may need to be exported; otherwise use checkpoints as the "learning" axis and say so). Note the paper only discusses energy landscapes (paper_facts).
6. `uncertainty` — "Where uncertainty lives (and where it does not)". IMPORTANT honest finding from our toy (data/toy2d.json _meta.findings): with MSE training on noisy targets, basin sharpness does NOT track noise (Hessian eigenvalues 0.78–0.92 while noise varies 10×; a mirrored control run confirms). Reason: Algorithm 1 only ever uses ∇_ŷE, so adding any c(x) to E changes nothing; energy LEVELS across contexts are not directly trained, and with MSE the noise level does not enter the expected gradient. Comparing candidates within one context (BoN) is grounded; comparing energies across contexts is not directly trained. Teach this as a real insight, then show where the paper does see uncertainty (text Fig 8 with cross-entropy targets, video Fig 11) and check whether our text toy's per-character energies (data/text.json uncertainty: easy vs hard groups) differ; report what the data shows. Original brief follows:  Facet 2. Low-noise vs high-noise contexts in the toy: basin width/curvature (Hessian eigenvalues of E at the minimum, computed live by finite differences), energy level at the minimum, spread of GD endpoints from many starts, basin_stats. Link to paper Fig 8/11 (cite) and to why continuous-space uncertainty is hard for feed-forward models (Sec 6.1). Equations: local quadratic approx $E(\hat y)\approx E^*+\tfrac12(\hat y-\hat y^*)^\top H(\hat y-\hat y^*)$ ⇒ Gaussian width $\propto H^{-1/2}$ if one reads $e^{-E}$ as a density (careful: unnormalized; say "relative").

### Part III · Thinking (inference)
7. `descent` — DONE by the lead (reference panel). Do not edit.
8. `langevin-bon` — "Exploring with noise, choosing by energy". Langevin dynamics $\hat y_{i+1}=\hat y_i-\alpha\nabla E+\eta_i,\ \eta_i\sim\mathcal N(0,\sigma^2 I)$ (Sec 3.3); Algorithm 2 (Best-of-N self-verification, M candidates, argmin energy, p.7); interactive: M particles with σ slider on the toy landscape (choose a context with a less trivial landscape or an earlier checkpoint where local minima exist), highlight argmin; second figure: text toy bon results (energy-select vs oracle vs mean CE for M=1,2,4,8) + paper Table 2 (Langevin removal: better single-path, worse with verification). Explain why noise trades single-path quality for diversity that verification can exploit.
9. `tokens` — "Thinking over a whole vocabulary". How text predictions work in EBT (paper_facts: ŷ = logits / distribution over vocab; embedding via p·W; check exact details), using the text toy: pick an example context, scrub steps 0..N, top-8 probability bars + entropy + energy; easy vs hard character energy heatmap (characters × steps) like paper Fig 8 alongside the paper's Fig 8 crop; dynamic stopping rule (stop when ΔE < ε) and how many steps easy vs hard characters would use; the toy thinking curve (val CE vs steps for EBT, flat baseline line; OOD splits). Equations: $p=\mathrm{softmax}(\hat y)$, $e=p^\top W$, cross-entropy $J=-\log p_{y}$.

### Part IV · Training
10. `alg1` — "Training: unroll the optimization, then backpropagate". Algorithm 1 (p.7) as an interactive computation graph: ŷ0 → [E, ∇] → ŷ1 → … → ŷN → J(ŷN, y); user chooses N (1–6); forward pass animates left→right; backward pass right→left through every step to θ. Include a live mini-training demo you can step: a tiny 1-D or 2-D EBT with 2–3 parameters trained in-browser with exact gradients through the unrolled steps (e.g. $E_\theta(\hat y)=\tfrac{a}{2}(\hat y-b x)^2$ or similar), showing loss, the parameters, and the landscape updating after each [ train step ]. Explain losses per modality (cross-entropy text, MSE images, Smooth-L1 video).
11. `second-order` — "Gradients of gradients". Derive $\frac{\partial J}{\partial\theta}$ through one step: $\hat y_1=\hat y_0-\alpha\nabla_{\hat y}E_\theta(\hat y_0)$ ⇒ $\frac{\partial\hat y_1}{\partial\theta}=-\alpha\,\nabla_\theta\nabla_{\hat y}E$ and through N steps the Jacobian chain $\prod(I-\alpha H_{\hat y\hat y})$; Hessian-vector products cost ~one extra backward pass (Pearlmutter), linear in model size (Sec 3.2, Sec I.2 pseudocode, cost F+B+B ≈ 3.33× a Transformer++ step per paper_facts). Interactive: a 1-D example where the user drags θ and sees the unrolled path and dJ/dθ computed analytically vs by finite differences; show what happens if you detach (stop-gradient) the inner gradient (first-order approximation) vs exact.
12. `contrastive` — "Why train by optimizing instead of contrasting". Contrastive EBM training (push down positives, push up negatives) and the curse of dimensionality (Sec 3.2, p.6–7): interactive: dimension slider showing the fraction of space covered by K negatives (volume argument) or how many random negatives land near the data manifold; vs optimization-based training which shapes the landscape only along the paths the optimizer actually takes (implicit regularization, convex around the truth). GAN analogy (p.7). Toy illustration ok (concept tag).
13. `regularizers` — "Shaping a landscape you can think on". Replay buffer, Langevin noise, randomized step size, randomized number of steps (Sec 3.3, appendix values from paper_facts, unspecified ones marked unspecified). Table 2 interactive bars with explanation of each row; toy replay_buffer_demo; what each regularizer does to the landscape (toggle illustrations, concept tag where not from data). S1 vs S2 recipes (paper_facts).
14. `learning` — "Watching a landscape learn". Toy2d checkpoint scrubber (step 0 → 12000): landscape for 2 contexts morphing, training loss curve with cursor, GD trajectories at that checkpoint, thinking_by_ckpt / bon_vs_training (does thinking/verification improve with training? relate to paper Fig 6b honestly).
15. `architecture` — "Inside an EBT". How a candidate prediction enters a Transformer (decoder-only AR EBT and bidirectional EBT; Sec 3.4, C.3), the information-leakage problem when predicting all next tokens in parallel and how the paper's attention scheme fixes it (paper_facts, derived explanation labelled), the energy head producing a scalar per position, cost accounting per step (forward + backward to input, ~3.33× / 6.66× numbers from paper_facts), model sizes used. Interactive: an attention-mask diagram where hovering a position shows which observed tokens and which candidate predictions it may attend to; a toggle "naive" vs "paper's scheme" that shows the leak.
